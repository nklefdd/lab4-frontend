# Jewelry Store — фронтенд

Навчальний фронтенд крамниці прикрас на HTML, CSS і JavaScript. Використовує `fetch`, без npm, збирання та фреймворків.

Бекенд: [web-programming-lab4](https://github.com/nklefdd/web-programming-lab4).

## Як запустити проєкт

1. У папці бекенду встановіть залежності з `requirements.txt`, виконайте `python manage.py migrate` і запустіть `python manage.py runserver`.
2. У папці цього фронтенду виконайте:

   ```bash
   python -m http.server 5500
   ```

3. Відкрийте `http://127.0.0.1:5500` у браузері.

| Частина | Адреса |
| --- | --- |
| Фронтенд | `http://127.0.0.1:5500` |
| Бекенд | `http://127.0.0.1:8000` |
| API | `http://127.0.0.1:8000/api` |

Бекенд дозволяє CORS-запити з `http://127.0.0.1:5500` і `http://localhost:5500`. Відкривайте сторінки через сервер, а не через `file://`. Адресу API можна змінити в `app/auth.js`.

## Сторінки

- `index.html` — відкритий каталог, список прикрас, фільтри, пошук, сортування та вікно з деталями.
- `pages/register.html` — реєстрація з повідомленнями про помилки полів.
- `pages/login.html` — вхід за логіном і паролем.
- `pages/profile.html` — дані поточного користувача, доступні лише після входу.

Гість бачить кнопки входу та реєстрації. Авторизований користувач бачить своє ім’я (або логін) та кнопку виходу.

Якщо відкрити профіль без входу, відкриється `pages/login.html?next=profile.html`. Після входу користувач повернеться у профіль. Посилання на реєстрацію теж зберігає цю адресу. Авторизованого користувача зі сторінок входу та реєстрації перенаправляє в каталог.

## Токени та logout

Після входу access і refresh зберігаються в `sessionStorage` поточної вкладки. Профіль завантажується через `GET /api/auth/me` із хедером `Authorization: Bearer <access>`.

У `app/auth.js` функція `getCurrentUser()` робить цей запит. Якщо access завершився і сервер повернув 401, функція надсилає refresh на `POST /api/auth/refresh`, зберігає новий access і один раз повторює запит профілю. За недійсного refresh токени видаляються, а профіль перенаправляє на вхід. При тимчасовій помилці мережі токени залишаються, сторінка показує повідомлення.

Кнопка «Вийти» видаляє обидва токени та відкриває каталог. Закриття вкладки також завершує клієнтську сесію. Logout не відкликає токени на сервері.

Додавання, редагування та видалення каталогу доступне адміністратору через API/Postman. Фронтенд показує каталог і профіль, без форм редагування товарів.

## Структура проєкту

```text
lab4-frontend/
├── .github/
│   └── pull_request_template.md
├── app/
│   ├── app.js
│   ├── auth.js
│   ├── login.js
│   ├── register.js
│   └── profile.js
├── assets/
├── pages/
│   ├── login.html
│   ├── register.html
│   └── profile.html
├── styles/
│   └── style.css
├── .gitignore
├── index.html
└── README.md
```

- `index.html` — головна сторінка каталогу.
- `pages/` — сторінки реєстрації, входу та профілю.
- `app/` — JavaScript: каталог, авторизація та логіка сторінок.
- `styles/` — спільні стилі.
- `assets/` — зображення, шрифт і його ліцензія.
- `.github/pull_request_template.md` — шаблон опису Pull Request із завданням, описом змін і поясненням використання ШІ.

Сервер потрібно запускати з кореня проєкту, де лежить `index.html`.

## Перевірка

1. Відкрийте профіль без входу: має відкритися логін.
2. Зареєструйтеся та увійдіть: відкриється профіль, у меню з’явиться ім’я.
3. Відкрийте `pages/login.html` після входу: відкриється каталог.
4. Зачекайте понад 5 хвилин і знову відкрийте профіль. Access оновиться через refresh без повторного входу. У Network браузера видно 401, запит refresh із 200 і повторний запит профілю із 200.
5. Натисніть «Вийти»: обидва токени зникнуть із Session Storage, профіль знову вимагатиме входу.


## Дизайн і каталог

Інтерфейс українською, назва магазину — Jewelry Store. Шапка залишається видимою під час прокручування; переходи до розділів враховують її висоту. Основні кольори — молочний, чорний та жовто-зелений акцент. Шрифт Manrope і головне зображення збережені в `assets`, тому для їх завантаження не потрібні зовнішні сервіси.

Пошук працює за назвою, описом, категорією та матеріалом. Можна відсортувати прикраси за ціною або назвою. Кнопка з ціною та стрілкою відкриває деталі прикраси; закрити їх можна кнопкою × або клавішею Escape. Дані надходять з наявного API. Нові моделі, міграції та додаткові бібліотеки не потрібні.

Зображення на першому екрані — декоративна арткомпозиція, а не фотографія товару. Вигаданих товарів у коді немає. Якщо база порожня, каталог показує відповідне повідомлення. Фото товарів можна буде додати окремо, коли в API з’явиться поле зображення.

Референси:

- [Дія](https://diia.gov.ua/) — помітні основні дії, контрастна типографіка й виразна кольорова площина.
- [GUNIA Project](https://guniaproject.com/) — великий предметний кадр і стримана навігація.
- [COS](https://www.cos.com/en-gb/women) — редакційна подача колекцій і короткі підписи.
- [KOCHUT](https://kochut.ua/) — увага до назви, матеріалу та конкретних характеристик прикраси.

Це власна композиція для навчального проєкту. Логотипи, фотографії та код цих сайтів не використовуються. Походження локальних ресурсів описане в `assets/README.md`.
